# r8 — candidate8을 두 요소로 나눠 보기: 극대 집합 × 열거 반지름 여유, 그리고 극대 집합 수 대 배열 꼭짓점 수

candidate8은 저자 코드와 두 군데가 다르다.

- **극대 집합**: 기저 사례에서 원판 배열의 꼭짓점을 모두 판정하는 대신, 상자 안의 극대 집합마다 증인점 하나만 판정한다.
- **여유**: 열거 반지름을 δ에서 δ + s로 넓힌다. s는 판정자 여유 9×10⁻⁹ 중 반올림에 쓰지 않는 부분이다.

r7의 4.55배에는 두 요소의 몫이 섞여 있다. r8은 두 가지를 쟀다(2026-11-01 23:45 – 11-02 03:26).

1. **2×2 절제 실험**: 네 방식을 r5와 같은 방식으로 한 측정에서 번갈아 쟀다. 대상은 값 계산(LMF)이다(Characters 21,000쌍, Sigspatial 1,000쌍).
2. **계수 실행**: candidate8이 실제로 들어간 기저 사례 판정마다 다음 둘을 셌다.
   - 같은 상자·원판·반지름에서 저자 코드가 판정할 배열 꼭짓점 수
   - candidate8의 극대 집합 수

자세한 표는 [`RESULTS.md`](RESULTS.md)에 있다.

| | 여유 없음 (반지름 δ) | 여유 있음 (반지름 δ + s) |
|---|---|---|
| 배열 기저 사례 | **A** 저자 코드 (`authors_gitlab/`) | **A+s** 저자 코드 + 여유 (`patches/authors_slack.patch`) |
| 극대 집합 기저 사례 | **c7** candidate7 | **c8** candidate8 |

## 요약

1. **여유는 저자 코드에도 똑같이, 또는 더 크게 듣는다.** "여유는 우리 방식에서만 중요하다"는 예상은 맞지 않았다.

   | 여유의 효과 | Characters 총 / 기하평균 | Sigspatial 총 / 기하평균 | 판정자 호출 감소 (Ch / Sig) |
   |---|--:|--:|--:|
   | 배열 기저 사례 (A ÷ A+s) | **1.39× / 1.48×** | 1.28× / 1.25× | 1.47× / 1.35× |
   | 극대 집합 기저 사례 (c7 ÷ c8) | 1.24× / 1.40× | 1.28× / 1.23× | 1.22× / 1.23× |

   모두 유의하다. Characters에서는 100쌍 묶음 210개 중 207개, 196개가 빨랐고, Sigspatial에서는 p ≤ 5×10⁻¹¹이다.

2. **극대 집합의 효과는 여유와 상관없이 남는다.** 같은 여유 조건끼리 비교한 값이 극대 집합만의 기여다.

   | 극대 집합의 효과 | Characters 총 / 기하평균 [95 % CI] | Sigspatial 총 / 기하평균 [95 % CI] |
   |---|--:|--:|
   | 여유 없음 (A ÷ c7) | 3.79× / 3.82× [3.79, 3.86] | 28.4× / 2.83× [2.69, 2.96] |
   | 여유 있음 (A+s ÷ c8) | **3.38× / 3.61×** [3.58, 3.64] | **28.5× / 2.78×** [2.64, 2.92] |

3. **전체 효과를 두 몫으로 나누면, 나누는 순서에 따라 값이 조금 다르다.**
   - Characters 전체 4.71배(A ÷ c8)는 "여유 1.39배 × 극대 집합 3.38배"로도, "극대 집합 3.79배 × 여유 1.24배"로도 나뉜다.
   - 두 값이 다른 것은 여유의 효과가 배열 쪽에서 더 크기 때문이다(기하평균 1.48 대 1.40).
   - Sigspatial에서는 여유의 효과가 두 쪽에서 같다(1.25 대 1.23).
   - 그래서 극대 집합의 몫은 Characters 3.4–3.8배, Sigspatial 기하평균 2.8배로 쓴다.
4. **극대 집합 수는 배열 꼭짓점 수보다 약 35배 적다.** 서론의 가설이 맞다.

   | | 기저 사례 판정 | 후보 수: 저자 방식 V / candidate8 K (합계 비, 판정별 중앙값) | 실제 판정자 호출 비 (저자 방식 ÷ candidate8) |
   |---|--:|--:|--:|
   | Characters | 1,251,210 | 35.4× / 36.0× | **14.8×** |
   | Sigspatial | 81,831 | 34.1× / 31.6× | **15.3×** |

   - 저자 방식의 후보는 절단 원판 m과 함께 빠르게 늘어 m = 12에서 평균 130개 안팎이다. 극대 집합은 평균 3.5개 이하다([`fig_counts.pdf`](fig_counts.pdf)).
   - 극대 집합의 개수는 여유와 무관하다(K와 K0의 합계 차이가 0.01 % 미만).
   - 따라서 여유가 빠르게 하는 이유는 후보 수가 아니다. 상자를 일찍 끝내기 때문이다(아래 2절).
5. **값은 네 방식 모두 저자 코드와 10⁻⁷ 안이다.**
   - 여유를 준 두 방식은 저자 코드보다 조금 아래로 간다. 중앙값은 A+s −5.0×10⁻⁹, c8 −5.1×10⁻⁹이다(Characters).
   - c7은 +2.4×10⁻⁹ 위로 간다.

## 1. 측정 조건

- **기계**: 서버 컨테이너(Intel Xeon @ **2.80 GHz**, 2 vCPU), 커널 6.18.
  - r5–r7(2.10 GHz)과 다른 CPU다. 그래서 절대 시간은 r7과 비교하지 않는다.
  - 다만 같은 측정 안의 비는 r7과 비슷하다. A ÷ c8이 r7에서 4.55× / 5.09×, r8에서 4.71× / 5.35×다(Characters).
- **소프트웨어**: r7과 같다. g++ 13.3, CGAL 5.6(GMPXX), Boost 1.83, GMP 6.3.0 / MPFR 4.2.1(Ubuntu 패키지)이다. 저장소는 29d6c93이다. 기록은 [`raw/r8_timing.tar.xz`](raw/r8_timing.tar.xz)의 `log.txt`에 있다.
- **방식**: r5와 같다.
  - CPU 1에 고정하고 CPU 0은 비웠다.
  - Characters는 100쌍 묶음마다, Sigspatial은 쌍마다 네 방식을 별도 프로세스로 연달아 실행했다.
  - 순서는 여덟 가지를 돌려, 각 방식이 각 자리에 같은 횟수씩 서게 했다.
  - 저자 코드 두 방식은 Sigspatial에서 5 GB 주소 공간 제한을 걸었다. 비정상 종료는 0이다(프로세스 4,840개).
- **A+s**(`patches/authors_slack.patch`): 저자 코드의 `N6Alg::lessThan(distance, …, box)`에서 배열 원판의 반지름만 δ + s로 바꿨다.
  - s는 candidate8과 같은 식이다: s = max(0, η − e − η/9), e = candidate8의 `deciderRoundingBound`.
  - 판정은 그대로 δ + η에서 한다.
  - `AUTHORS_SLACK=0`으로 돌리면 저자 코드와 값·호출 수가 비트 단위로 같다(첫 묶음 100쌍에서 확인).
  - 정확성 근거는 candidate8과 같다([`candidate8/README.candidate8.md`](../../candidate8/README.candidate8.md) 3절, s ≤ η − e). 정확 오라클 가족으로는 검증하지 않았다.
- **c7**은 `candidate7/` 빌드에 `MAXREGION_SLACK=0`을 줬다. 첫 묶음에서 r6의 candidate7과 값·호출 수가 같다.
- **계수 실행**(`patches/candidate8_count.patch`)은 candidate8에 계수 코드만 더했다.
  - 판정마다 다음을 기록한다.
    - m: 절단 원판 수
    - V: 같은 원판·반지름 δ·상자로 저자 코드의 `ArrangementTraversal(discs, box)`가 내는 꼭짓점 수
    - K: candidate8의 상자 family 크기(반지름 δ + s)
    - K0: 같은 상자 family를 반지름 δ로 셌을 때의 크기
    - 판정 횟수: 저자 방식(꼭짓점을 CGAL 순서로 첫 YES까지)과 candidate8
  - 측정과 상관없는 실행이라 두 CPU를 썼다.
  - 계수 실행의 값은 타이밍 측정의 candidate8과 21,000 / 21,000, 1,000 / 1,000 인스턴스에서 같다.

## 2. 해석

- **여유가 하는 일**
  - 기저 사례의 이분 탐색은 판정자의 여유 안에서 조금 더 낮은 값에 멈춘다(약 5×10⁻⁹).
  - 그러면 전역 상한이 더 빨리 내려가고, `max − min_dist ≤ ε/2`로 끝나는 상자가 많아지는 것으로 보인다. 직접 센 것은 아니고, 판정자 호출과 Lipschitz 호출·배열 추정 시간이 함께 줄어든 데서 추론했다.
  - 이 효과는 기저 사례의 종류와 상관없다.
  - 저자 코드는 상자 하나에 배열을 만드는 비용이 커서, 끝내는 상자 하나당 아끼는 시간이 더 크다.
  - 실제로 A+s는 Characters에서 배열 단계 시간이 2,287 s에서 1,582 s로, 배열 추정이 196 s에서 119 s로 줄었다.
- **c7이 저자 코드보다 느렸던 이유(r5의 190쌍)와의 관계**
  - c7은 값이 저자 코드보다 위(+2.4×10⁻⁹)에서 멈춰 상자를 오래 남겼다.
  - 여유는 이 차이를 메우고, 거기서 더 내려간다.
  - 같은 여유를 저자 코드에 주면 저자 코드도 같은 만큼 내려간다(−5.0×10⁻⁹).
  - 따라서 여유는 "증인점이 교집합 안쪽에 있어서 잃은 것을 되찾는 장치"라기보다, **판정자의 허용 오차를 정확성을 해치지 않고 쓰는 일반적인 방법**이다.
- **극대 집합의 효과**
  - 같은 조건에서 3.4–3.8배(Characters), 기하평균 2.8배(Sigspatial)다.
  - 기저 사례에서 판정할 후보가 약 35배, 실제 판정자 호출이 약 15배 줄어서 생긴다.
  - 총 시간 비가 이보다 작은 것은 바꾸지 않은 단계(전처리, Lipschitz 호출, 배열 추정) 때문이다.

## 3. 논문에 넣는 방법 (제안)

- **기여를 둘로 나눈다.**
  1. 극대 집합 기저 사례: 후보 35배 감소, 판정 15배 감소. 같은 조건에서 값 계산 3.4–3.8배(Characters), 기하평균 2.8배(Sigspatial)다.
  2. 판정자 여유를 이용한 열거 반지름: 정확성 증명이 붙은 일반적 기법이다. 저자 코드에 적용해도 1.28–1.39배, 우리 방법에서는 1.24–1.28배 빨라진다.
- **5장 실험에 2×2 표를 넣는다.** 표는 이 폴더의 [`RESULTS.md`](RESULTS.md), 그림은 [`fig_ablation.pdf`](fig_ablation.pdf)다.
  - 전체 4.7배를 두 몫으로 나눠 보인다: 극대 집합 3.4–3.8배, 여유 1.24–1.39배(나누는 순서에 따라).
  - 극대 집합만의 효과를 묻는 질문에는 A+s ÷ c8로 답한다.
- **극대 집합 수 대 꼭짓점 수**: 3장 정리 뒤나 5장 처음에 [`fig_counts.pdf`](fig_counts.pdf)와 위 표를 넣는다. 서론 가설의 뒷부분("실제 데이터에서 훨씬 적다")의 근거가 된다.
- **V의 정의를 밝힌다.** V는 저자 코드가 실제로 시험하는 점이다.
  - 원판의 x 극점(원을 단조 호로 자를 때 생기는 점), 상자 꼭짓점과 변 교점, 상자 밖 원–원 교점이 모두 들어간다.
  - 순수한 배열 꼭짓점 수보다 크다.
- **서론과 초록의 수치를 바꿀지 정해야 한다.** r7의 "저자 코드 대비 4.55배"는 두 요소를 합친 값이다. 극대 집합의 몫(3.4배)과 여유의 몫(1.4배)을 함께 적는 것이 정직하다.
